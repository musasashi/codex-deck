# 使い方

[READMEに戻る](../README.md)

WSLに接続したVS Codeで使用します。CLI・認証・環境変数はWSL側に用意してください。作業フォルダーやファイルはWSL内のパスで扱います。Windowsドライブ上のフォルダーは`/mnt/c/...`などのパスで開きます。

## 複数タブ

「Codex Deck」上部の「＋」で新規タスク、「チャット履歴」で以前の会話を開きます。通常のエディタと同様にタブを分割でき、エクスプローラーの「開いているタスク」で一覧と状態を確認できます。

完了した回答をまだ見ていないタスクには、一覧の右端に青点が付きます。対象のタブで回答を表示すると消えます。

## プリセット

1. 「Codex Deck」の歯車ボタン、またはコマンド「Codex Deck: 設定」を開きます。
2. 保存先をユーザー・ワークスペース・各フォルダー（複数ルート時）から選び、モデル・推論強度・権限の組を追加・編集・並べ替えます。
3. 「保存」を押します。先頭のプリセットが新規タスクの初期値になります。

送信ボタンのすぐ左にある切り替えボタン、またはCtrl+Tabで、プリセットを順番に切り替えます。キーバインドはVS Codeの「キーボード ショートカット」でコマンド「Codex Deck: 次のプリセットに切り替え」に別のキーを割り当てられます。現在の設定が一覧に一致しない場合は先頭を適用します。実行中は切り替えできません。

初期設定は、モデル `latest`・推論強度 `high`・権限 `Approve for me`です。`latest`は会話の開始時または切り替え時に、利用可能な推奨モデルと更新先からモデルを選びます。

タスクのモデル・推論強度・権限は入力欄下部から個別にも変更できます。履歴から開いた会話は保存済みの設定を引き継ぎます。

設定画面の「タスク名」では、自動要約に使うモデルと推論強度を変更できます。新規タスク・分岐先とも、最初の依頼を送信した後に要約用の推論を使います。

### Hugging Face経由のモデル

1. [HFのトークン設定](https://huggingface.co/settings/tokens)で、**Make calls to Inference Providers**権限を持つトークンを作成します。
2. WSL内の`.bashrc`などに`export HF_TOKEN='トークン'`を記述します。設定後は「Developer: Reload Window」でウィンドウを再読み込みしてください。拡張機能ホストに変数がない場合、App Serverの起動時にWSL内の対話シェルから読み込みます。
3. 「Codex Deck: 設定」でプリセットを追加し、モデルに「Hugging Face（モデルIDを指定）」を選びます。
4. HFのモデルIDを`組織/モデル`または`組織/モデル:プロバイダー`の形式で入力します。入力・出力単価（**USD／100万トークン**）は任意です。「利用可否を確認」で基本動作を確認できます。設定の保存では推論APIを呼び出しません。
5. 新規タスクでそのプリセットへ切り替え、依頼を送信します。OpenAIのタスクと同時に実行できます。

設定JSONでは`model`に`hf:`を付けます。次の`model`と`pricing`を確認したモデルID・接続先・単価に置き換えてください。

```json
{
  "model": "hf:org/model:provider",
  "effort": "default",
  "mode": "workspace-write",
  "pricing": { "input": 0.1, "output": 0.2 }
}
```

モデルIDと接続先は[HFのモデル一覧](https://huggingface.co/inference/models)で確認してください。推論強度はモデルの既定値を使用します。タスク名のモデルが`latest`の場合、HFタスクの要約にも同じHFモデルと単価を使用します。要約用のHFモデルと単価を別途指定することもできます。

接続には[HFのResponses API](https://huggingface.co/docs/inference-providers/en/guides/responses-api)を使用します。ツール定義をHFが受け付ける形式に変換し、HFが入力として受け付けない推論項目を履歴から除きます。推論強度にはHFモデルの既定値を使い、Codex側の強度を引き継ぎません。

### Responses API接続先を追加する

1. 「Codex Deck: 設定」の「Responses API接続先」で「接続先を追加」を押します。
2. 表示名・接続先ID・Base URL・APIキーの環境変数名を入力します。Base URLは`/responses`の前までです。認証不要のローカルAPIでは環境変数名を空欄にできます。
3. モデルIDを追加します。画像入力・対応する推論強度・構造化出力は、提供元とモデルの仕様に合わせて設定してください。
4. プリセットまたはタスク名のモデル候補から登録したモデルを選び、保存します。単価は任意です。「利用可否を確認」は保存とは独立した操作です。

接続先はユーザー設定の`codexDeck.providers`に保存します。APIキーの値は保存せず、WSL内の指定した環境変数から読み込みます。設定ファイルで指定する場合の例です。URLとモデルIDは利用するAPIの値に置き換えてください。

```json
{
  "codexDeck.providers": [{
    "id": "my-api",
    "name": "My API",
    "baseUrl": "https://api.example.com/v1",
    "apiKeyEnv": "MY_API_KEY",
    "models": [{ "id": "model-id", "images": false, "reasoningEfforts": [], "structuredOutput": false }]
  }],
  "codexDeck.presets": [{ "model": "responses:my-api:model-id", "effort": "default", "mode": "workspace-write" }]
}
```

接続先IDは会話の識別に使うため、利用開始後も維持してください。新規タスクでは保存した接続先設定を使用します。会話の接続先は作成時に確定し、再開・分岐でも引き継ぎます。同じ接続先のモデルは切り替えられます。異なる接続先を使う場合は、新規タスクでプリセットを選択してください。タスク名のモデルが`latest`の場合、外部APIタスクでは同じモデルと単価を使用します。

接続先にはResponses APIのテキスト応答・SSEストリーミング・関数ツール呼び出し・ツール結果を含む会話継続が必要です。会話履歴は毎回送信し、サーバー側の履歴保存には依存しません。「OpenAI互換」でもChat CompletionsのみのAPIは対象外です。対応範囲は[Open Responses仕様](https://www.openresponses.org/specification)と提供元のドキュメントで確認してください。

### 外部APIの確認と費用

HF・Responses APIのタスクでは、入力欄下部にそのタスクの**累計費用（USD・概算）**を表示します。設定した単価と使用トークン数から計算し、外部APIでのタスク名要約も含めます。単価と残高は自動取得しません。累計は再起動後も保持し、分岐先は分岐後の利用分を計測します。単価を変更しても、過去の計上額は変わりません。単価未設定・計測開始前の利用がある場合は、その旨を表示します。無料クレジット・キャッシュ割引は未反映です。

「利用可否を確認」では、固定のテスト文でJSON形式の要約、ツール呼び出しと結果返却後の回答、利用トークン数を検証します。要約専用モデルではツール検証を省きます。モデルごとに最大3回の短いリクエストを送り、料金は提供元に請求されます。ファイルやタスクの会話は送信しません。失敗・中止時は理由と入力内容を画面に残します。この確認は画像入力や推論強度など全機能の互換性を保証するものではありません。

外部APIタスクにはOpenAIの残量ゲージと自動継続予約を表示しません。Codexのユーザー設定ファイルは変更しません。

### 権限

| 設定 | 意味 |
| --- | --- |
| Ask for approval | 承認が必要な操作を利用者が確認する |
| Approve for me | 承認要求を自動レビューへ送る |
| Full Access | サンドボックスと承認確認を使用しない |
| Read Only | 読み取り専用 |
| Codex設定を引き継ぐ | Codex側の権限設定を使う |

## 使用量の残量

入力欄下部に5時間枠・週次枠の残量ゲージを表示します。カーソルを合わせるかTabキーでフォーカスすると、残りの割合とリセット予定時刻を確認できます。取得できない枠は表示しません。

## 自動継続予約

タブ右上の「使用量回復後に自動継続」をONにします。初期値はOFFで、使用量上限で停止した後からもONにできます。文字にカーソルを合わせると動作条件を確認できます。**VS Codeが起動し、App Serverに接続している間に動作します。**

使用量の回復を確認すると、同じ会話へ継続指示を自動送信します。回復を確認できない場合は待機を続けます。通常の完了や使用量以外のエラーでは自動継続しません。

| 操作 | 予約への影響 |
| --- | --- |
| チェックをOFFにする | 予約を解除 |
| 「停止」を押す・タスクのタブを閉じる | 予約を解除し、チェックもOFF |
| 手動でメッセージを送信する | それまでの予約を解除 |

閉じたタブを開き直しても、自動継続はOFFのままです。再び自動継続するにはチェックをONにしてください。

VS Codeの再起動時にタブを復元すると、予約も復元して使用量と実行状態を確認します。送信結果が不明なまま終了した場合は、重複を防ぐため自動で再送しません。

## その他の操作

既定ではCtrl+Enterで送信、EnterまたはShift+Enterで改行します。送信ボタンにカーソルを合わせると、現在の送信キーを確認できます。実行中に送ったメッセージは、そのターンへの追加入力になります。

| 操作 | 方法 |
| --- | --- |
| ファイルのパスを入力 | `@`で検索して選択 |
| ファイル・画像を添付 | 入力欄下部の「＋」。画像はCtrl+Vでも貼り付け可能 |
| 選択した文章に言及 | エディタやCodexの回答で文章を範囲選択し、右クリック→「Codex-Deckで言及」 |
| スキルを使用 | `$`または`/skills`で選択 |
| 会話をコピー | タスク一覧で右クリック→「コピー」→ディープリンクまたはMarkdown |
| 応答から分岐 | Codexの本文にカーソルを合わせ、「新しいチャットに分岐」 |
| 履歴をアーカイブ・復元 | 履歴の行の右端をクリックし、もう一度クリックして確定。復元は「アーカイブした履歴」から選択 |

「Codex-Deckで言及」は、参照元と選択した文章を入力欄の末尾に引用形式で追加します。そのまま続けてコメントを入力し、送信してください。エディタからの言及では、対象のタスクが複数ある場合に選択します。

分岐先のタスク名は、最初の新しい指示を送信した時点で、その指示と引き継いだ会話を要約して付けます。名前が付くまでは「分岐したタスク」と表示されます。要約に失敗した場合は、次の指示送信時に再試行します。

ディープリンクを別タスクに貼り付けても、会話本文は入力欄や送信済みメッセージに展開されません。送信時点の会話をWSL内の一時ディレクトリ（`/tmp`など）に保存し、Codexが必要に応じて読みます。入力本文の下に「参照情報（Codex Deckが自動追加）」を折りたたんで表示します。同じ接続先の履歴を取得できる必要があります。

参照用ファイルの削除時期はOSの管理に従います。削除後に再び参照する場合は、リンクを送信し直してください。

コードレビュー・MCP・worktree作成はタスク右上の「•••」から操作できます。`/`で利用できるコマンドを表示・絞り込みできます。

コマンド候補はEnterで実行、Tabで入力欄に補完します。引数のないコマンドは、Tab補完後もEnterで実行できます。指示を続けて入力した場合は、通常の送信キーを使います。

`/plan`でプランモードを切り替えます。`/plan 指示`はプランモードに切り替えて指示を送信します。画像やスキルも添付できます。通常モードに戻すには、実行が完了してからもう一度`/plan`を送信してください。モードはタスクごとに保存され、モデル・権限・プリセットを変更しても維持されます。

## 困ったとき

| 状況 | 対処 |
| --- | --- |
| WSL専用の案内が表示される | 作業フォルダーをWSL接続で開き、Codex Deckと公式Codex CLIをWSL側にインストール |
| CLIが見つからない | WSL内で`codex --version`を確認し、VS Codeの設定`codexDeck.cliPath`に`codex`またはWSL内の実行ファイルのパスを指定 |
| 未接続 | タスク右上の「•••」→「App Serverに再接続」 |
| `Missing environment variable: HF_TOKEN` | WSL内の`.bashrc`などに`HF_TOKEN`を設定し、「Developer: Reload Window」を実行。ターミナル内だけの設定は引き継がれません |
| エラーの詳細を見たい | 操作した画面と、出力パネルの「Codex Deck」を確認 |
